# X Thread 2 — What PSA Is and the 3 Levels

---

**Tweet 1 (Hook)**
You do not need a third-party tool to harden Kubernetes pods.

Pod Security Admission is built into Kubernetes. One label enforces security rules on every pod automatically. Here is how it works 🧵

---

**Tweet 2**
Pod Security Admission gives you three levels to choose from:

Privileged, Baseline, and Restricted.

Each one is stricter than the last. Most teams run at Privileged by accident because they never turned it on.

---

**Tweet 3**
Privileged = Zero restrictions at all.

This is for Kubernetes system components only. etcd, kube-proxy, things that actually need low-level access. Never use this for your applications.

---

**Tweet 4**
Baseline = Blocks the most dangerous misconfigurations.

No privileged containers. No hostNetwork access. No privilege escalation. A solid starting point if you are starting from zero.

---

**Tweet 5**
Restricted = Heavily locked down.

Enforces non-root, capability drops, and privilege escalation prevention on every single pod automatically. This is the target for production.

---

**Tweet 6**
The key thing most people miss: you are not writing custom rules.

Kubernetes already wrote the rules. You are just choosing how strictly to apply them. Pick a level, add a label, Kubernetes handles the rest.
