# Post — Renovate + Continuous Delivery (X / Twitter)

---

**Tweet 1**
The last step in implementing continuous delivery in my home lab was automating image tag updates.

Turns out I was still doing it by hand. Here is how I fixed that 🧵

---

**Tweet 2**
Every time a new version of an app got published I had to go into my repo, find the deployment manifest, and bump the tag manually.

That is not automation. That is just moving the manual work to a different place.

---

**Tweet 3**
Renovate fixed that.

It watches the registry for new image tags. When a new version gets published it opens a pull request in my home lab repo suggesting the version bump automatically.

---

**Tweet 4**
The full chain now looks like this:

1. New Docker image published to registry
2. Renovate detects the new tag
3. Renovate opens a PR in my repo
4. I review and merge
5. Flux updates the running pod

I never touch the manifest directly.

---

**Tweet 5**
GitOps can actually automate the merge as well. But I deliberately keep that manual step.

Every update goes through my eyes before it hits the cluster. I see what changed, what version it moved to, and I make the call.

That is how I stay on top of what is running in my environment and why.

---

**Tweet 6**

Intentional automation is better.
