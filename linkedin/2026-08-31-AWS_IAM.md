My learning focus has been AWS, I'll be sitting for the AWS SAA exam soon, and the first thing I want to share is my understanding of IAM.

It is an integral part of AWS as it controls who is allowed in your AWS account and what they can do once inside. IAM is very security focused when it comes to its policies. Nothing is allowed in AWS by default (unless you are the root user, which sits outside IAM's rules). Every permission has to be explicitly granted and if not it is blocked.

There are three types of identities: users, groups, and roles. Individual resources can also have their own policies attached to them. Before any action is allowed on AWS, the policies of all involved parties are pooled and evaluated as a whole. The rule it follows: explicit deny, explicit allow, implicit deny.

Meaning: if there is an explicit deny in the pooled policy, we will be blocked. If there are no denies and explicit allows grant us permission, we are able to execute the action. If there are no explicit denies or allows then we are also blocked by default. Hopefully you start to see how security focused AWS is by design.
